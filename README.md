# InfoMed

[![CI](https://github.com/balbino-z/infomed-tcc/actions/workflows/ci.yml/badge.svg)](https://github.com/balbino-z/infomed-tcc/actions/workflows/ci.yml)

InfoMed is a public-health mobile web app (PWA) for **Santa Bárbara d'Oeste (SP), Brazil**. Citizens can check which medicines are available at each basic health unit (UBS), find units on a map, book and cancel appointments, and set medication reminders. It is the final-year project (TCC) of a Systems Information course.

> **Academic project.** Health units (names, addresses, phones, hours and services) come from the city hall's public pages. **Medicine stock and doctors are simulated** for demonstration. See `docs/data/fontes-unidades.md`.

## Features

- Medicine search and per-unit availability (simulated stock)
- 15 real health units, list and map (Leaflet + OpenStreetMap), open/closed status, "near me" sorting
- Unit filters: open now, distance, services, medicine available (Strategy pattern)
- Appointment booking (consultation, follow-up, exam) with business rules enforced in the database
- Appointment history and cancellation
- Medication reminders and in-app alerts (while the app is open)
- Notifications created by the server on booking and cancellation
- Sign-up / login with LGPD (Brazilian data-protection law) consent recorded per user
- Installable PWA, deep links and a working back button

## Architecture

```
src/app/
  components/screens/   UI screens (originally generated with Figma Make, then refactored)
  domain/               entities and types
  repositories/         interfaces + implementations (mock/ and supabase/)
  features/             auth, navigation, units (+filters), scheduling, notifications, reminders
  lib/supabase.ts       Supabase client (null when .env is missing)
db/                     numbered SQL scripts (01..07) and db/ci (CI helpers and database tests)
docs/                   ADRs, feature sheets, diagrams, security tests, evidence
```

Design patterns: **Repository** (data access), **Factory** (appointment creation), **Observer** (notifications and reminders) and **Strategy** (unit filters and sorting). Screens never talk to the database directly; `repositories/index.ts` is the only place that chooses between the mock and Supabase implementations.

## Getting started

Requirements: Node.js 20 or newer (22 recommended) and Git.

```bash
git clone https://github.com/balbino-z/infomed-tcc.git
cd infomed-tcc
npm install
cp .env.example .env     # then fill in your Supabase values
npm run dev
```

Without a `.env` file the app runs in **mock mode** (in-memory fake data), which is also what the tests use.

| Variable | Description |
|---|---|
| `VITE_SUPABASE_URL` | Supabase project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase publishable (public) key. **Never use the secret / service_role key** |

### Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Development server |
| `npm run typecheck` | TypeScript check (`tsc --noEmit`) |
| `npm test` | Unit and integration tests |
| `npm run build` | Production build (PWA) |

### Database

Run the scripts in `db/` in order in the Supabase SQL editor: `01_schema`, `02_seed`, `04_auth`, `05_postos_reais` (generated by `scripts/gerar-sql-unidades.mjs`), `06_agendamento`, `07_lembretes`. `03_teste_rls.sql` is a manual isolation test.

## Continuous integration

Every push and pull request to `main` runs two jobs (`.github/workflows/ci.yml`):

1. **App**: `npm ci`, type check, tests and production build.
2. **Database**: starts PostgreSQL 16, creates stand-ins for Supabase (roles and `auth` schema), applies the migration scripts and runs `db/ci/tests.sql`, which checks row-level security, appointment rules and reminder validations.

Merging to `main` triggers an automatic deploy on Vercel (continuous delivery).

## Documentation

All decisions are recorded in `docs/decisions` (ADR-001 to ADR-013) and each feature has a sheet in `docs/features`. Start with `docs/README.md`.

## Known limitations

- Reminder alerts only fire while the app is open (PWA limitation); background push is future work.
- iOS native distribution is out of scope; the PWA can be added to the home screen.
- Map tiles use the public OpenStreetMap servers, which is fine for a demo but not for heavy traffic.
